## 1. Установка дистрибутива и настройка сети

Для выполнения проекта установлена РЕД ОС 8 с архитектурой ARM64 в виртуальной машине UTM.

Сетевое подключение настроено в режиме DHCP.

**Выполненные настройки:**

- Сетевой интерфейс: `enp0s1`.
- Метод назначения IPv4-адреса: DHCP.
- Имя компьютера: `mephi-2026.domain.local`.
- Проверена доступность внешнего IP-адреса `8.8.8.8`.

Команда проверки:

`ping -c 4 8.8.8.8`

**Результат:** 4 пакета передано, 4 получено, потери — 0%.

Результат сохранён в файле `ping.out`.

## 2. Управление программным обеспечением

Выполнено обновление пакетов операционной системы с использованием пакетного менеджера DNF.

Установлены обязательные пакеты:

| Пакет | Назначение |
|---|---|
| `nginx` | Веб-сервер |
| `libcap-ng-utils` | Утилиты для управления привилегиями |
| `tcpdump` | Захват и анализ сетевого трафика |

В рамках задания предусмотрена работа с бинарным RPM-пакетом `tcpdump`, включая скачивание через `dnf download` и установку командой `rpm`.

Наличие пакетов проверено командой:

`rpm -q nginx libcap-ng-utils tcpdump`

История операций пакетного менеджера сохранена в `dnf.out`.

## 3. Управление файловыми системами

Для хранения данных веб-проекта использован дополнительный виртуальный диск `/dev/vdb` объёмом 10 ГиБ.

На диске создан один раздел:

`/dev/vdb1`

Раздел отформатирован в файловую систему **ext4** с меткой:

`MEPHI_WEB`

Создана точка монтирования:

`/mephi-web`

Для автоматического монтирования в `/etc/fstab` добавлена запись:

`LABEL=MEPHI_WEB /mephi-web ext4 defaults 0 2`

Успешность монтирования проверена с помощью `findmnt /mephi-web`.

После перезагрузки раздел автоматически подключается к `/mephi-web`.

Подтверждающие файлы: `fstab`, `stat.out`.

## 4. Управление системными сервисами

Установлен и настроен веб-сервер **nginx**.

Для службы включён автоматический запуск при загрузке системы.

В конфигурации nginx в качестве корневой директории сайта указана:

`/mephi-web`

В каталоге создан файл:

`/mephi-web/index.html`

Содержимое страницы:

**Hello from Student: 375027**

Проверки:

- `systemctl is-active nginx` — `active`.
- `systemctl is-enabled nginx` — `enabled`.
- `curl http://localhost/` — возвращает страницу студента.

Для анализа работы веб-сервера использована утилита `journalctl`.

Журнал службы за текущую загрузку сохранён в `journalctl.out`.

## 5. Управление доступом к ресурсам

### 5.1. Дискреционное управление доступом (DAC)

Создана директория проекта:

`/data/mephi-2026`

Созданы три учётные записи разработчиков:

| Пользователь | UID | Группа |
|---|---:|---|
| user1 | 5501 | mephi-dev |
| user2 | 5502 | mephi-dev |
| user3 | 5503 | mephi-dev |

Для кураторов созданы две учётные записи:

| Пользователь | Группа | GID |
|---|---|---:|
| curator1 | curators | 4444 |
| curator2 | curators | 4444 |

Для директории проекта настроены дискреционные права доступа и расширенные списки контроля доступа POSIX ACL.

Установлены следующие правила:

- Разработчики имеют права чтения и записи файлов проекта.
- Кураторы имеют права чтения без возможности модификации файлов.
- Посторонним пользователям запрещён доступ к директории.
- Установлен бит set-GID для наследования группы-владельца.
- Настроены ACL по умолчанию для вновь создаваемых объектов.

**Практические проверки:**

1. `user1` создал файл в директории проекта.
2. `user2` успешно изменил файл, созданный `user1`.
3. `user3` успешно прочитал этот файл.
4. `curator1` смог прочитать файл, но получил отказ при попытке изменения.
5. Пользователь `nobody` получил отказ при попытке доступа к директории.

Права доступа сохранены после перезагрузки.

Подтверждающие файлы: `acl.out`, `stat.out`, `passwd`, `group`.

### 5.2. Управление привилегиями (Capabilities)

Для программы `tcpdump` применён механизм Linux Capabilities вместо предоставления полных прав root через Set-UID.

Исполняемый файл:

`/usr/sbin/tcpdump`

Назначенная привилегия:

`cap_net_raw=ep`

Проверена возможность запуска tcpdump от имени обычного пользователя `user1`.

В ходе тестирования выполнен захват ICMP-пакетов на интерфейсе `lo`.

**Результат:**

- Захвачено пакетов: 2.
- Получено фильтром: 4.
- Потеряно ядром: 0.

Успешный захват подтвердил возможность работы tcpdump без запуска от имени root.

Подтверждающие файлы: `getcap.out`, `tcpdump-test.out`.

### 5.3. Мандатное управление доступом (MAC)

Для защиты системы используется SELinux.

Рабочий режим:

**Enforcing**

Проверка выполнялась командой `getenforce`.

Для нестандартной директории `/mephi-web` настроены контексты безопасности, позволяющие nginx обслуживать размещённые в ней файлы.

Работоспособность веб-сервера подтверждена при включённом режиме SELinux Enforcing.

Подтверждающие файлы: `getenforce.out`, `selinux-context.out`, `curl.out`.

## 6. Аутентификация пользователей

### 6.1. Ограничение локального входа

Для управления локальным входом пользователей используется PAM.

В файле `/etc/pam.d/login` настроено правило:

`account required pam_succeed_if.so user notingroup curators`

Данное правило предназначено для запрета локального консольного входа пользователям группы `curators`.

Обычные пользователи сохраняют возможность входа в систему.

Подтверждающий файл: `pam-login.out`.

### 6.2. Политика паролей

Настроены следующие требования:

| Параметр | Значение |
|---|---|
| Максимальный срок действия пароля | 90 дней |
| Минимальная длина пароля | 12 символов |

В `/etc/login.defs` установлено:

`PASS_MAX_DAYS 90`

Для существующих пользователей срок действия паролей настроен с помощью `chage`.

В `/etc/security/pwquality.conf` заданы значения:

- `minlen = 12`
- `dcredit = 0`
- `ucredit = 0`
- `lcredit = 0`
- `ocredit = 0`

Проведена проверка смены пароля от имени обычного пользователя `user1`.

**Результат:** система отклонила пароль короче 12 символов.

Подтверждающие файлы: `pwquality.conf`, `password-aging.out`, `password-quality.out`.
